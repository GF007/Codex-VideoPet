# 视频状态切换与少帧动画设计规范

## 官方切换逻辑的核心

本机 Codex Desktop `26.730.8199` 的 spritesheet 帧渲染器没有做状态间 crossfade、补间或骨骼混合。状态改变时直接从新状态的第 0 帧开始；状态不变时不重启动画。非 `idle` 动作播放三遍后进入 `idle` 循环，而不是永久重复动作。减少动态效果时只显示该状态第 0 帧。App 外层仍可能有布局、透明度或缩放过渡，这里只讨论角色动作帧。

当前内置 Codex 使用 v2 spritesheet：`1536×2288`、11 行，单元为 `192×208`；前 9 行延续 v1 的九状态动作，后 2 行用于方向注视。下表是当前 renderer 仍在使用的前九行帧数和一轮时长：

| 状态 | 帧数 | 单帧节奏 | 一轮时长 |
| --- | ---: | --- | ---: |
| `idle` | 6 | `280/110/110/140/140/320 ms` 再整体乘 6 | 6600 ms |
| `running-right` | 8 | 前 7 帧 120 ms，末帧 220 ms | 1060 ms |
| `running-left` | 8 | 前 7 帧 120 ms，末帧 220 ms | 1060 ms |
| `waving` | 4 | 前 3 帧 140 ms，末帧 280 ms | 700 ms |
| `jumping` | 5 | 前 4 帧 140 ms，末帧 280 ms | 840 ms |
| `failed` | 8 | 前 7 帧 140 ms，末帧 240 ms | 1220 ms |
| `waiting` | 6 | 前 5 帧 150 ms，末帧 260 ms | 1010 ms |
| `running` | 6 | 前 5 帧 120 ms，末帧 220 ms | 820 ms |
| `review` | 6 | 前 5 帧 150 ms，末帧 280 ms | 1030 ms |

少帧仍自然的关键不是增加补间，而是选择正确的关键姿势并让重要姿势停得更久。官方普遍在动作末帧增加 70–140 ms 的停顿，`idle` 更把微动作拉成 6.6 秒的低频循环。

## 动画原则

1. **分层锚点系统**：所有片段共享相同的角色比例、脚底线、镜头、光照和背景，但不强迫所有循环使用同一个姿势。一次性动作从 `idle_anchor` 出发并返回；`waiting/running/review/failed` 的循环分别从自己的状态锚点开始并回到该锚点。进入和退出片段负责在锚点之间连接。
2. **三段动作弧线**：用 `预备姿势 → 主要动作 → 落定姿势` 表达状态。预备幅度小但方向明确；主要动作只保留一个视觉动词；落定帧必须可读并延长停留。
3. **在低速度点切换**：手落下、脚着地、身体回正、呼吸峰谷等瞬间最适合硬切。不要在腾空、挥手峰值、身体强倾斜或粒子爆发时允许退出。
4. **姿势停留替代无效帧**：先按 8–12 fps 设计 4–10 个关键姿势，再以重复帧编码到 24 fps。展示 pose 的时间通常比补很多相似中间帧更有价值。
5. **一次只表达一个语义**：`waiting` 是期待，`failed` 是受挫，`review` 是完成待查看。避免在同一短片里同时跑、挥手、转镜头和释放大特效。
6. **角色身份不能漂移**：脸型、肩宽、服装边缘、道具位置、阴影和裁切必须跨状态一致。生成式视频尤其要锁定这些参数。
7. **镜头完全固定**：不缩放、不平移、不改变焦距；方向状态只移动或倾斜角色，不移动相机。

## 九个逻辑状态应如何设计

这里的九项是状态语义，不代表最终只能有九个永久循环视频。持续状态应进一步拆成 `enter → loop → exit`；完整的制作资源和命名规范见 [`video-state-machine-asset-production-spec.md`](video-state-machine-asset-production-spec.md)。

| 状态 | 建议动作 | 安全首尾与循环方式 |
| --- | --- | --- |
| `idle` | 呼吸、眨眼、耳朵或衣摆轻动 | 中性微循环；首尾像素尽量对齐，周期 4–7 秒 |
| `running` | 专注工作、快速敲击或能量流动，不必真的奔跑 | 中性进入，形成稳定工作循环；建议补独立素材，不长期复用左右拖动视频 |
| `waiting` | 轻微探身、抬眼或期待手势 | 动作后停在可读的期待 pose；尾部只保留低幅呼吸 |
| `failed` | 短促受挫反应、低头或肩部下沉 | 结束冻结在失败 pose，不要自动弹回开心中性姿态；恢复 `idle` 时另走中性出口 |
| `review` | 注意到结果、确认或轻点头 | 手势落下后回中性并停留，表达“已完成，等你查看” |
| `waving` | 手下垂 → 预备抬手 → 挥 2–3 次 → 手落下 | 一次性问候；首尾均为同一中性 pose |
| `jumping` | 蹲下预备 → 离地 → 顶点 → 落地 → 回弹落定 | 脚底/地面是锚点，落地后至少保留 2 个关键姿势的 settle |
| `running-left` | 身体向左发力、迈步或拖动反馈 | 与右向共享完全相同的中性起止帧；方向由身体和脚步表达 |
| `running-right` | 身体向右发力、迈步或拖动反馈 | 与左向共享完全相同的中性起止帧；反向切换前先经过中性帧 |

## 当前视频素材的视觉结论

当前 `VideoSource/V1` 代表素材均为 `720×1280`、24 fps、97 帧、约 4.04 秒、无音频。基于 0–3.5 秒、每 0.5 秒一帧的接触表抽样：

- `idle`、`waiting` 首尾和镜头最稳定，适合整段循环。
- `waving`、`review` 已有“抬手再放下”的动作弧线，但必须确保手完全落下后才允许切换。
- `jumping` 中段姿态变化较大，脚底和落地不够明确；应强化蹲、起、落、settle 四个关键点。
- `failed` 尾部明显返回中性，不适合作为失败终态永久循环；应把低头/下沉姿势保持到末尾。
- `running-left/right` 主要是上身反向倾斜，运动语义偏弱，左右互切会发生脸、肩和重心跳变。
- 最大的共性风险不是帧数少，而是各视频中的中性角色也存在头肩比例、胸廓和姿势差异。跨片硬切时会出现角色“变形式 pop”。

接触表保存在 `artifacts/video-motion-review-20260805`。以上是抽样帧视觉核验，不代替逐帧播放和真实窗口切换验收。

## 当前 A/B 播放器约束下的制作方案

目前未设置 A-B Loop 的状态视频会在接近尾部时预载同一状态资源池中的下一条，并用约 5 帧完成旧片尾到新片头的交叉淡化。因此每条资源仍必须满足：

- 片头与片尾都尽量回到同一中性锚点，降低交叉淡化中的重影和形体漂移；
- 片尾保留约 0.3–0.6 秒低动作安全区；
- 同一状态的候选之间能够相互衔接；
- 不在末尾留下悬空、举手、倾斜或爆发特效。

需要保持单条素材尾段时，为该资源设置 `loop.start_ms/end_ms`：播放器先播前段，在 B 前预载同一文件并定位到 A，然后让两个运动画面同时播放约 5 帧完成尾到头的淡化。这种显式 A-B 资源不会参与自然 EOF 轮换。稳定阶段只保留一个 libmpv handle；状态切换、整片轮换或 Loop 接缝期间短暂使用两个，淡化结束立即释放旧 handle。视频槽透明度不会作用到 Direct2D 的 Session 卡片或状态面板。

V1 还支持状态级 `transition_policy`。默认 `immediate` 立即提交新视频；`finish_current_clip` 则由播放器保留当前片段，并将普通状态变化合并成一个 latest-wins 下一目标，到片尾预加载窗口才切换。该策略不依赖固定延时或文件总时长；`waiting/failed/review` 仍可抢占。当前 `waving` 与 `jumping` 启用，分别保证挥手完整收回，以及 hover 结束后仍完成蹲起、腾空、落地和 settle。

## 动画交付验收

1. 每个状态检查首帧、中性返回帧和最终落定帧；脚底、比例、镜头应一致。
2. 逐帧检查动作峰值、落地、手势回收和生成式角色漂移。
3. 做 `idle ↔ 8 个状态`、`running-left ↔ running-right`、注意状态相互切换的 5 帧交叉淡化测试；确认两侧画面都在运动且没有黑帧。
4. 连续随机切换至少 10 分钟，记录明显 pop、重影、亮度下陷或接缝停帧；素材锚点不一致仍应回到素材本身修复。
5. 确认同状态重复事件不重启视频；稳定阶段活动播放器回到 1，淡化窗口最多 2，Session 卡片和状态面板透明度不变。
